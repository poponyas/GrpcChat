# GrpcChat

Терминальный чат на Go: группы, личные переписки, переключение между чатами и сообщения в реальном времени через gRPC. Пользователи, участники, сообщения и сессии хранятся в PostgreSQL.

## Быстрый запуск

Нужны Go **1.25.12+**, Docker с Compose v2 и `make`. Сгенерированные protobuf-файлы уже в репозитории: `protoc` для запуска не нужен.

```sh
make setup       # создаёт .env из примера, только если файла ещё нет
make env-up      # PostgreSQL + локальный порт 127.0.0.1:5432
make migrate-up  # применяет обе миграции
make build       # bin/chat-server и bin/chat-cli
./bin/chat-server
```

Если `.env` остался от старого проекта, сверь его с `.env.example`. `POSTGRES_HOST=127.0.0.1` и `POSTGRES_PORT=5432` нужны для сервера, запущенного на хосте. При занятом порте поменяй проброс в Compose и `POSTGRES_PORT`. Миграции выполняются внутри Docker-сети и используют порт базы `5432`.

Если запуск завершается с `password authentication failed` (`SQLSTATE 28P01`), проверь, что `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB` в `.env` соответствуют существующей базе. Docker-образ использует эти параметры для создания роли и базы только при первом запуске с пустым каталогом данных. Замена `.env` или пересоздание контейнера с прежним `out/pgdata` не меняет пароль и не создаёт нового пользователя. Для сохранения данных укажи действующие реквизиты; копирование значений из `.env.example` их не восстановит.

Экспортированные переменные `POSTGRES_*` в терминале имеют приоритет над `.env` при запуске сервера. Если в них остались старые значения, убери соответствующие переменные из окружения и повтори запуск.

В другом терминале зарегистрируйся и открой клиент:

```sh
./bin/chat-cli register --name alice --fullname 'Алиса'
./bin/chat-cli
```

Пароль вводится без отображения символов; от 8 до 128 байт. Повторный запуск использует сохранённую сессию. Войти в существующий аккаунт: `./bin/chat-cli login --name alice`. Выйти с отзывом сессии: `./bin/chat-cli logout`. `/quit` закрывает клиент, сохраняя вход.

Сессия хранится в пользовательской конфигурационной директории: на Linux обычно `~/.config/grpcchat/session.json`. Файл создаётся с правами `0600`. `--session /path/account.session.json` выбирает другой файл; `--addr host:port` задаётся при регистрации/входе. Пароль в файле не сохраняется.

### Попробовать вдвоём на одном компьютере

Укажи разные файлы сессий, чтобы второй аккаунт не заменил первый:

```sh
# Терминал Алисы
./bin/chat-cli register --name alice --session /tmp/alice.session.json
./bin/chat-cli --session /tmp/alice.session.json

# Терминал Боба
./bin/chat-cli register --name bob --session /tmp/bob.session.json
./bin/chat-cli --session /tmp/bob.session.json
```

Если аккаунты уже созданы, используй `login` вместо `register`.

Алиса создаёт группу и приглашает Боба:

```text
/group Разработка
/invite bob
Привет, команда!
```

Боб выполняет `/chats`, затем `/open Разработка` и отвечает обычным текстом. Для личной переписки — `/dm alice`. Чтобы вернуться в группу — `/open Разработка`. При сообщении в другом чате появляется уведомление и увеличивается локальный счётчик новых сообщений.

## Команды клиента

| Команда | Действие |
| --- | --- |
| `/chats` | Обновить список своих групп и диалогов, показать номера и ID |
| `/open <номер\|имя\|ID>` | Перейти в чат и показать последние 30 сообщений |
| `/group <название>` | Создать группу и сразу открыть её |
| `/users [часть имени]` | Найти пользователя и узнать его ID |
| `/dm <@имя\|ID>` | Открыть или создать личный диалог с пользователем |
| `/members` | Показать участников текущего чата и их роли |
| `/invite <@имя\|ID>` | Добавить участника в текущую группу |
| `/remove <@имя\|ID>` | Удалить участника из текущей группы |
| `/leave` | Выйти из группы |
| `/history [1..100]` | Загрузить следующую страницу более старых сообщений |
| `/help` | Показать справку |
| `/quit` | Закрыть клиент |

Всё без `/` отправляется в открытый чат. `//пример` отправляет текст `/пример`. Названия групп могут содержать пробелы. Если названия совпадают, используй номер из последнего `/chats` или полный ID. Для неоднозначного имени пользователя используй ID из `/users`.

Приглашать и удалять участников может владелец группы. Участник может выйти сам. Владелец сначала удаляет остальных участников, затем выходит; пустая группа вместе с её историей удаляется. Состав личного диалога фиксирован: два разных пользователя. Новый приглашённый участник получает доступ ко всей истории группы.

Сообщение ограничено **4096 символами Unicode**. Клиент показывает подтверждённое сервером сообщение после записи в базу. Автоматической повторной отправки при ошибке нет: если соединение оборвалось во время отправки, проверь историю перед повтором.

## Подключение с другого компьютера

По умолчанию сервер слушает только `127.0.0.1:50051`. Для внешнего адреса задай `GRPC_HOST`, `GRPC_TLS_CERT`, `GRPC_TLS_KEY` в окружении или `.env`; сертификат должен соответствовать DNS-имени сервера. Сервер откажется слушать внешний адрес без TLS.

```sh
./bin/chat-cli login --addr chat.example.org:50051 --tls --name alice
./bin/chat-cli login --addr chat.example.org:50051 --ca /path/ca.pem --name alice
./bin/chat-cli
```

Параметры TLS сохраняются вместе с сессией. Пароль для сценариев автоматизации можно подать через `--password-stdin`; не передавай его аргументом командной строки.

## Проверка и разработка

```sh
make check  
make test   
make build


TEST_DATABASE_URL='postgres://chat:password@localhost:5432/grpcchat_test?sslmode=disable' make test-integration
```

Тесты интеграции проверяют реальные SQL-запросы, регистрацию/вход/выход, авторизацию, два стрима одного пользователя, историю с курсором, удаление участников, одновременное создание личного диалога и команды CLI с отправкой сообщений. GitHub Actions запускает проверки с отдельным PostgreSQL.

`make test` перечисляет каталоги исходников явно: локальная база лежит в `out/pgdata`, и Go не должен обходить её закрытые каталоги. `make env-down` останавливает контейнеры, сохраняя базу. Сервер и клиенты завершаются по Ctrl+C. Перед остановкой базы сначала заверши сервер.

При изменении контракта нужны `protoc`, `protoc-gen-go` и `protoc-gen-go-grpc`, затем `make grpc-codegen`.

## Что было и что готово

Исходный проект содержал CRUD профилей, схему PostgreSQL и заготовку чата. Клиента не было; чат не регистрировался на сервере; авторизация была заглушкой, а обработчик стрима ссылался на несуществующий ключ контекста.

Теперь собран рабочий MVP: аккаунты и сессии, группы с приглашениями, личные диалоги без дублей, переключение чатов, хранение и постраничная загрузка истории, доставка онлайн, несколько терминалов одного пользователя и переподключение.

Это клиент с построчным вводом. Счётчики новых сообщений живут только до закрытия клиента. После переподключения обновляется список чатов и загружаются последние 30 сообщений активного чата; более старые доступны через `/history`. Доставка онлайн работает в пределах одного серверного процесса. Полноэкранный интерфейс, постоянные отметки прочтения и другие следующие шаги описаны в [roadmap](docs/ROADMAP.md).

Подробное объяснение устройства и потоков данных: [архитектура](docs/ARCHITECTURE.md).
